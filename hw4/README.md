## Условие задачи
В небольшой парикмахерской работают несколько парикмахеров. Каждый парикмахер обслуживает одного посетителя в своем кресле. Имеется ограниченное количество стульев для ожидающих посетителей. Если посетителей меньше числа парикмахеров, то свободные парикмахеры «спят». При появлении нового посетителя один из парикмахеров просыпается и начинает обслуживание. Если все парикмахеры заняты, новый посетитель занимает свободный стул и становится в очередь. Если все стулья заняты, посетитель покидает парикмахерскую необслуженным. После завершения стрижки посетитель освобождает кресло и уходит. Парикмахер начинает обслуживать следующего ожидающего посетителя, а при пустой очереди засыпает.

**Цель:** Разработать распределённое консольное клиент-серверное приложение на языке C (с использованием `libc`, системных вызовов и сетевого API POSIX) для ОС Linux/POSIX с асинхронным взаимодействием процессов по протоколу TCP.

## Сценарий: отображение сущностей в сервер, клиенты и процессы (4–5 баллов)

Предметная область разделена на независимые консольные приложения, каждое из которых может быть запущено как на одном компьютере (`127.0.0.1`), так и на разных узлах сети.

### Ролевое распределение программ
1. **Парикмахерская — сервер (`barbershop_server`):**
    * Центральный узел, хранящий состояние зала ожидания (кольцевая очередь `g_queue[MAX_CHAIRS]` типа FIFO), таблицу подключённых клиентов (`g_clients[MAX_CLIENTS]`) и общую статистику (`пришло`, `обслужено`, `ушло`).
    * Асинхронно обслуживает все TCP-соединения в одном процессе с помощью системного вызова `poll()` (таймаут 200 мс), принимая новые подключения (`accept`) и обрабатывая входящие пакеты без блокировки остальных участников.
2. **Парикмахеры — клиенты (`barbershop_barber`):**
    * Каждый парикмахер запускается как отдельный независимый процесс со своим идентификатором (`-i`).
    * После подключения к серверу отправляет пакет регистрации `MSG_HELLO_BARBER` и переходит в состояние ожидания («спит» на чтении сокета).
    * Получив от сервера `MSG_ASSIGN_CUSTOMER` с идентификатором посетителя, имитирует стрижку случайной длительности (`nanosleep` в диапазоне `[m, M]` секунд), после чего отправляет серверу `MSG_HAIRCUT_DONE`.
3. **Посетители — многопроцессный генератор (`barbershop_customer`):**
    * Родительский процесс с заданной случайной задержкой порождает `n` независимых дочерних процессов через `fork()`.
    * Каждый процесс-посетитель открывает собственное TCP-соединение с сервером, регистрируется пакетом `MSG_HELLO_CUSTOMER` и ожидает ответа:
        * `MSG_CUSTOMER_WAIT` — посетитель занял свободный стул в очереди;
        * `MSG_CUSTOMER_SERVED` — стрижка завершена, посетитель покидает парикмахерскую;
        * `MSG_CUSTOMER_LEFT` — все стулья заняты, посетитель уходит необслуженным.

### Сетевой протокол (`protocol.h`, `net_utils.c`)
Для обмена между процессами по TCP используется бинарный пакет фиксированного размера `Packet`:
* `int32_t type` — тип сообщения из перечисления `MsgType` (`MSG_HELLO_BARBER`, `MSG_HELLO_CUSTOMER`, `MSG_HELLO_OBSERVER`, `MSG_ASSIGN_CUSTOMER`, `MSG_HAIRCUT_DONE`, `MSG_CUSTOMER_WAIT`, `MSG_CUSTOMER_SERVED`, `MSG_CUSTOMER_LEFT`, `MSG_OBSERVER_EVENT`);
* `int32_t id` — идентификатор парикмахера, посетителя или PID наблюдателя;
* `char text[256]` — текстовая полезная нагрузка для передачи событий наблюдателям.

Поля `type` и `id` при отправке и приёме переводятся между порядком байт хоста и сетевым порядком (`htonl`/`ntohl`), а функции `write_all` и `read_all` гарантируют полную запись и чтение структуры из потокового TCP-сокета.

На уровне 4–5 баллов сервер, парикмахеры и посетители выводят в консоль только локальные события, непосредственно относящиеся к ним, без общей сводной картины.

## Расширение на 6–7 баллов: отдельный клиент-наблюдатель

Для комплексного отображения работы всей системы разработана отдельная клиентская программа **`barbershop_observer`**, позволяющая отслеживать состояние парикмахерской целиком в одном окне терминала (и опционально записывать журнал в файл).

### Модификации в протоколе и сервере
* В `protocol.h` добавлены типы сообщений `MSG_HELLO_OBSERVER` (регистрация монитора) и `MSG_OBSERVER_EVENT` (событие системы).
* В `server.c` введена роль `ROLE_OBSERVER` и функция рассылки `broadcast_event()`, формирующая строку с временной меткой от старта сервера `[Время  XX.XXs]` и отправляющая пакет `MSG_OBSERVER_EVENT` наблюдателю при каждом значимом событии (выход мастера на смену, приход клиента, посадка в очередь, начало/завершение стрижки, уход необслуженного клиента, засыпание парикмахера).
* При подключении наблюдателя сервер сразу отправляет ему актуальную сводку: текущую заполненность очереди, количество обслуженных и ушедших посетителей.

## Расширение на 8 баллов: множество наблюдателей и динамическое переподключение

Реализована поддержка одновременной работы произвольного числа клиентов-наблюдателей (в пределах `MAX_CLIENTS = 128`) с возможностью подключать и отключать их в любой момент без влияния на работу сервера и моделирования:

* Все подключённые наблюдатели хранятся в общей таблице слотов `g_clients[]` с ролью `ROLE_OBSERVER`; функция `broadcast_event()` последовательно рассылает каждое событие всем активным наблюдателям.
* На сервере отключён сигнал `SIGPIPE` (`signal(SIGPIPE, SIG_IGN)`), чтобы запись в разорванный сокет не приводила к аварийному завершению процесса.
* При отключении любого наблюдателя (события `POLLHUP`/`POLLERR`/`POLLNVAL` в `poll()`, возврат `false` из `net_recv_packet()` или ошибка отправки в `broadcast_event()`) сервер логирует отключение и освобождает только соответствующий слот через `close_slot()`, продолжая штатную работу для остальных клиентов и наблюдателей.
* Повторно подключившийся наблюдатель занимает освободившийся слот, сразу получает актуальную сводку состояния парикмахерской и продолжает приём событий в реальном времени.

## Пользовательский интерфейс

Все программы реализованы как CLI-приложения с настройкой через аргументы командной строки (`getopt`).
* **Ввод-вывод через файловые дескрипторы:** вывод в терминал реализован через `dprintf(STDOUT_FILENO, ...)` (`log_stdout`), запись журнала наблюдателя — через системный вызов `open(..., O_WRONLY | O_CREAT | O_TRUNC, 0644)` и `dprintf(log_fd, ...)`, сетевой обмен — через системные вызовы `read()` и `write()`.
* **Информативность вывода:** сообщения содержат роль участника, идентификатор, состояние очереди (`X/N`), длительность стрижки и временную метку события.

## Сборка, варианты запуска и завершения

### Сборка
Проект собирается с помощью `CMake` (стандарт C11, флаги `-Wall -Wextra`) из директории `hw4/`:
```bash
cmake -B build
cmake --build build
```

### Варианты запуска
IP-адрес (`-a`) и порт (`-p`) задаются в командной строке каждого модуля. Для локального запуска используется `127.0.0.1`; для распределённого запуска на разных компьютерах в сети сервер запускается с `-a 0.0.0.0` (или конкретным IP-адресом интерфейса), а клиенты — с IP-адресом машины сервера.

1. **Сервер (`barbershop_server`):**
   ```bash
   ./build/barbershop_server -a <IP> -p <порт> -w <число_стульев>
   ```
   По умолчанию: `-a 127.0.0.1 -p 8080 -w 3` (допустимо от `1` до `64` стульев).

2. **Парикмахеры (`barbershop_barber`):**
   ```bash
   ./build/barbershop_barber -a <IP> -p <порт> -i <ID> -m <мин_сек> -M <макс_сек>
   ```
   По умолчанию: `-a 127.0.0.1 -p 8080 -i 1 -m 1.0 -M 3.0`. Можно запускать несколько экземпляров с разными `-i`.

3. **Наблюдатели (`barbershop_observer`):**
   ```bash
   ./build/barbershop_observer -a <IP> -p <порт> [-l <путь_к_логу>]
   ```
   По умолчанию: `-a 127.0.0.1 -p 8080`, запись в файл отключена. Можно запускать несколько независимых копий одновременно.

4. **Генератор посетителей (`barbershop_customer`):**
   ```bash
   ./build/barbershop_customer -a <IP> -p <порт> -n <число_клиентов> [-s <начальный_ID>] -m <мин_интервал> -M <макс_интервал>
   ```
   По умолчанию: `-a 127.0.0.1 -p 8080 -n 10 -s 1 -m 0.5 -M 1.5`.

### Сценарии завершения программы
* **Посетители и генератор (`barbershop_customer`):** каждый дочерний процесс завершается с кодом `0` сразу после получения `MSG_CUSTOMER_SERVED` или `MSG_CUSTOMER_LEFT` (либо при разрыве соединения). Родительский процесс дожидается всех `n` потомков через `wait(NULL)` и штатно завершается.
* **Наблюдатель (`barbershop_observer`):** корректно завершается по сигналам `SIGINT`/`SIGTERM` (`Ctrl+C`, обработчик установлен через `sigaction` без `SA_RESTART`, что немедленно прерывает блокирующий `read()`) либо при закрытии соединения сервером; закрывает сокет и файловый дескриптор лога.
* **Парикмахер (`barbershop_barber`):** завершается по `SIGINT`/`SIGTERM` (`sigaction`) либо автоматически при разрыве соединения с сервером.
* **Сервер (`barbershop_server`):** перехватывает `SIGINT`/`SIGTERM`, выходит из цикла `poll()`, печатает итоговую статистику (`пришло`, `обслужено`, `ушло`) и закрывает все активные клиентские сокеты и слушающий сокет.
