1 Задача о парикмахере  
В небольшой парикмахерской работают несколько парикмахеров. Каждый парикмахер обслуживает одного посетителя в своем кресле. Имеется ограниченное количество стульев для ожидающих посетителей. Если посетителей меньше числа парикмахеров, то свободные парикмахеры «спят». При появлении нового посетителя (включая первого) один из парикмахеров просыпается и начинает обслуживание. Если все парикмахеры заняты, новый посетитель занимает свободный стул и становится в очередь. Если все стулья заняты, посетитель покидает парикмахерскую необслуженным. После завершения стрижки посетитель освобождает кресло и уходит. Парикмахер начинает обслуживать следующего ожидающего посетителя, а при пустой очереди засыпает.  
Требуется разработать многопоточное консольное приложение для ОС Linux/POSIX с синхронизацией потоков через мьютексы и семафоры.  

Входные параметры:  
• количество парикмахеров (`barber_count`);  
• количество стульев для ожидания (`waiting_chairs`);  
• количество посетителей (`total_customers`);  
• диапазон интервалов появления посетителей (`min_arrival_interval`, `max_arrival_interval`);  
• диапазон продолжительности стрижки (`min_haircut_time`, `max_haircut_time`);  
• предельное время симуляции (`max_sim_time`);  
• начальное значение генератора случайных чисел (`random_seed`).  

Отображаемые события:  
Программа сообщает о появлении посетителя, уходе из-за отсутствия стульев, занятии стула ожидания, пробуждении парикмахера, приглашении клиента, завершении стрижки, освобождении кресла и засыпании парикмахера.  

Инварианты:  
• в кресле обслуживания находится не более одного посетителя;  
• парикмахер обслуживает не более одного посетителя одновременно;  
• посетитель не может одновременно ожидать на стуле и обслуживаться;  
• число ожидающих в очереди строго не превышает количество стульев (`waiting_chairs`);  
• каждый принятый посетитель обслуживается не более одного раза.  

Завершение:  
Моделирование завершается после обслуживания всех запланированных посетителей, по истечении предельного времени симуляции или по прерыванию пользователем (`SIGINT` / `Ctrl+C`) с корректным завершением всех активных потоков.  

Каждый парикмахер и каждый посетитель являются самостоятельными параллельными участниками модели и функционируют как отдельные потоки ОС.

Задание реализовано на языке С в стандарте C11 с разбиением на независимые модули и использованием библиотеки `pthread`:  
* **types.h** — общие структуры данных и синхропримитивы:  
  * `Barber` — сущность мастера: дескриптор потока `pthread_t`, статус (`BARBER_SLEEP` или `BARBER_WORK`), текущий клиент, счетчик обслуженных клиентов и указатель на парикмахерскую.  
  * `Customer` — сущность клиента: метки времени прихода, начала стрижки, окончания стрижки, `id`, указатель на `Barbershop` и персональный именованный семафор `sem_service_done` для ожидания завершения стрижки.  
  * `Barbershop` — контекст модели: кольцевая очередь стульев ожидания (FIFO), счетчик очереди, мьютекс `mutex` (`pthread_mutex_t`) для защиты общего состояния очереди и семафор `sem_customers` (`sem_t`) для сигнализации спящим мастерам.  
  * `Config` — параметры моделирования, загружаемые из файла или по умолчанию.  
  * `Statistics` — общие метрики (прибыло, подстрижено, ушло без стрижки, время ожидания).  
* **logger.h / logger.c** — потокобезопасный модуль логирования:  
  * Вывод в консоль и в файл журнала реализован через низкоуровневые системные дескрипторы (`dprintf`, `open`, `close`).  
  * Вывод защищен глобальным мьютексом `g_log_mutex`, что исключает гонку данных (Data Race) и перемешивание строк от одновременно пишущих потоков.  
* **barbershop.h / barbershop.c** — многопоточная логика и взаимодействие:  
  * `barbershop_thread` — рабочий цикл парикмахера: при отсутствии людей засыпает на `sem_wait(sem_customers)`, просыпается по сигналу, берет клиента из кольцевой очереди FIFO, имитирует стрижку через масштабированную задержку `usleep()`, сигнализирует клиенту через `sem_post(customer->sem_service_done)` и возвращается к проверке очереди.  
  * `customer_thread` — поток посетителя: под защитой `shop->mutex` проверяет наличие стульев; при отсутствии мест уходит, при наличии — садится в очередь, будит парикмахера `sem_post(shop->sem_customers)`, отпускает мьютекс и блокируется на `sem_wait(customer->sem_service_done)` до окончания стрижки.  
  * Проверка инварианта непустой очереди при извлечении клиентуры контролируется через `assert(shop->waiting_count > 0)`.
* **main.c** — точка входа программы:  
  * Обработка CLI-аргументов (`-c`, `-l`), чтение конфигурационного файла.  
  * Инициализация синхропримитивов и запуск потоков мастеров (`shop_start`).  
  * Главный цикл порождения потоков клиентов с интервалами задержки (`usleep`).  
  * Регистрация и перехват сигнала `SIGINT` (`signal(SIGINT, handle_sigint)`).  
  * Корректный `pthread_join` для потоков клиентов и завершение работы мастеров через `shop_stop` с выводом итоговой статистики.  

## Пользовательский интерфейс  

Пользовательский интерфейс выполнен в виде потокобезопасного CLI с поддержкой записи журнала на диск:  
1. Вывод сообщений осуществляется напрямую через системные дескрипторы файлов с помощью функции `dprintf`.  
2. Запись лога в файл инициализируется системным вызовом `g_log_fd = open(log_file, O_WRONLY | O_CREAT | O_TRUNC, 0644);`.  
3. Каждая строка вывода содержит форматированное время и действие: `[Время   X.XXs] <описание события>`.  
4. Детализированы все состояния: вход клиента, занятие стула с указанием заполненности очереди (`в очереди: X/Y`), пробуждение мастера, стрижка, уход подстриженного клиента или уход из-за отсутствия свободных мест.

## Сценарии завершения  

1. **Штатное завершение по объёму данных:** наступает, когда все запланированные клиенты сгенерированы, их потоки завершили выполнение (`pthread_join`), мастера завершили стрижку оставшихся в очереди людей, после чего потоки парикмахеров корректно закрываются и освобождаются ресурсы.  
2. **Штатное завершение по тайм-ауту:** если общее время работы превышает параметр `max_sim_time`, генерация новых потоков клиентов прекращается, обслуживаются уже сидящие в очереди клиенты и программа подводит итог.  
3. **Принудительное завершение по прерыванию (`SIGINT` / `Ctrl+C`):**  
   * В программе зарегистрирован обработчик `signal(SIGINT, handle_sigint)`.  
   * При получении сигнала взводится флаг `g_sigint_received` типа `sig_atomic_t`.
   * Прекращается создание новых клиентов, все спящие мастера будятся через сигналы семафора для безопасного выхода из рабочих циклов, все созданные потоки завершаются через `pthread_join`, закрываются семафоры, мьютексы и дескриптор файла журнала, после чего выводится собранная статистика.
