## Условие задачи
В небольшой парикмахерской работают несколько парикмахеров. Каждый парикмахер обслуживает одного посетителя в своем кресле. Имеется ограниченное количество стульев для ожидающих посетителей. Если посетителей меньше числа парикмахеров, то свободные парикмахеры «спят». При появлении нового посетителя один из парикмахеров просыпается и начинает обслуживание. Если все парикмахеры заняты, новый посетитель занимает свободный стул и становится в очередь. Если все стулья заняты, посетитель покидает парикмахерскую необслуженным. После завершения стрижки посетитель освобождает кресло и уходит. Парикмахер начинает обслуживать следующего ожидающего посетителя, а при пустой очереди засыпает.

**Цель:** Разработать многопроцессное консольное приложение для ОС Linux/POSIX с межпроцессным взаимодействием (IPC) через разделяемую память и семафоры.

## Сценарий: отображение сущностей в процессы и их взаимодействие
Каждый парикмахер и каждый посетитель являются самостоятельными параллельными участниками модели и функционируют как **отдельные процессы ОС**, обменивающиеся данными через общую разделяемую память (`shm_open`, `mmap`).

1. **Разделяемая память (`BarbershopShared`):** Хранит кольцевую очередь ожидания (FIFO), конфигурацию, общую статистику и объекты синхронизации (мьютекс для защиты памяти и семафор для подсчета клиентов в очереди).
2. **Процесс-Парикмахер:** 
   * В бесконечном цикле пытается захватить семафор очереди клиентов (`sem_wait(&g_shop->customer_sem)`). Если очередь пуста, процесс блокируется операционной системой (парикмахер «спит»).
   * Как только семафор открывается, парикмахер захватывает мьютекс разделяемой памяти, извлекает клиента из очереди ожидания, имитирует стрижку (`usleep`) и отправляет сигнал завершения в персональный семафор клиента (`sem_post(&customer->sem)`).
3. **Процесс-Посетитель:** 
   * При появлении захватывает глобальный мьютекс и проверяет наличие свободных стульев.
   * Если мест нет, инкрементирует счетчик ушедших клиентов, отпускает мьютекс и завершает свой процесс (уходит).
   * Если места есть, инициализирует свой персональный семафор ожидания, копирует свои данные в кольцевую очередь разделяемой памяти, увеличивает глобальный семафор очереди (`sem_post(&g_shop->customer_sem)` — будит мастера) и засыпает на своем персональном семафоре, ожидая окончания стрижки.

### Структура версий (Критерии оценки)
В репозитории представлены три независимые реализации:
* **`mark5/` (4-5 баллов):** Процессы создаются через `fork()` из одного файла. Синхронизация через именованные семафоры (`sem_open`).
* **`mark6/` (6 баллов):** Процессы создаются через `fork()`. Синхронизация через неименованные семафоры (`sem_init` с флагом `pshared=1`), размещенные прямо в структуре разделяемой памяти.
* **`mark8/` (7-8 баллов):** Клиент-серверная архитектура. Система разделена на две полностью независимые программы:
  * `barbershop_server`: Инициализирует разделяемую память, создает семафоры и запускает процессы парикмахеров.
  * `barbershop_client`: Программа-генератор. Подключается к уже существующей разделяемой памяти и порождает заданное количество процессов-клиентов. 

## Пользовательский интерфейс
Интерфейс реализован в виде потокобезопасного CLI-приложения с поддержкой записи журнала событий.
* **Формат вывода:** Каждое событие сопровождается временной меткой от начала симуляции: `[Время   X.XXs] <Событие>`.
* **Логирование:** Осуществляется через низкоуровневые дескрипторы (`dprintf`). Доступ к выводу в терминал и файл защищен глобальным именованным семафором, что гарантирует отсутствие гонки данных (Data Race) и предотвращает «склеивание» строк от независимых процессов.

## Сборка и запуск программы

Проект использует систему сборки `CMake`. Сборка выполняется из корня директории нужной оценки:

### Варианты запуска (на примере версии 8 баллов)
Сервер запускается в первом терминале (или в фоновом режиме `&`):
```bash
# Запуск с конфигурацией из файла и записью логов
./build/barbershop_server -c ../data/config.cfg -l run.log
```
Генератор клиентов запускается из второго терминала (параметр `-n` задает число посетителей):
```bash
./build/barbershop_client -n 15
```

## Сценарии завершения программы
1. **Естественное завершение клиента:** Утилита `barbershop_client` дожидается (`waitpid`) завершения всех сгенерированных ею процессов-клиентов, выводит сообщение об успехе и штатно завершается, освобождая локальные ресурсы.
2. **Завершение сервера по тайм-ауту:** Если время работы сервера превышает параметр `max_sim_time`, сервер прекращает ожидание, дожидается обслуживания оставшихся клиентов, выводит итоговую статистику и удаляет объекты разделяемой памяти (`shm_unlink`, `munmap`).
3. **Прерывание пользователем (Ctrl+C / `SIGINT`):** Сигнал перехватывается зарегистрированным обработчиком. Сервер безопасно будит всех спящих парикмахеров, дожидается их завершения, закрывает файловые дескрипторы логов и очищает системные ресурсы IPC.
